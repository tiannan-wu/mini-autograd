# 60 行手写 autograd：数值梯度对拍误差 1e-11

> English version: [README](../README.md)

## 我做了什么

从零写了一个标量自动微分引擎。核心是一个 `Value` 类，它同时干四件事：

- 存数值 `data`
- 存累积的梯度 `grad`
- 存自己的输入 `_prev`（由构造参数 `_children` 去重得到）
- 存一个闭包 `_backward`，知道"收到梯度后该怎么分给我的输入"

每个运算（`+ - * / ** exp log relu tanh`）只做两件事：算出新的值、挂上对应的闭包。前向时不计算任何梯度。

反向时先对整张计算图做拓扑排序（DFS 后序再反转），把种子 `self.grad = 1.0` 放好，然后倒序遍历，逐个调用 `_backward()`。

最后用**中心差分**验证：`(f(x+h) - f(x-h)) / 2h` 和解析梯度对比。

## 结果

6 组表达式、12 项断言，`atol=1e-10, rtol=1e-6`：

| 测试 | 相对误差 |
|---|---|
| 复合表达式（tanh / pow / log） | 1.7e-12 ~ 3.2e-11 |
| 共享节点（`x*x + x*y`） | 7.5e-12 ~ 3.7e-11 |
| relu | 2.1e-12 ~ 5.6e-12 |
| 除法 / 减法 | 3.2e-12 ~ 1.9e-11 |
| exp（sigmoid） | 2.5e-11 |
| 深链（50 层 tanh） | 2.5e-3 \* |

\* 深链那项的梯度只有 3.5e-9，而 `f(x±h)` 的值在 1 附近，相减时丢了一位有效数字——**这个 0.25% 是"检查方法"的精度地板，不是引擎的误差**。

我用 60 位精度的 `mpmath` 算了真值对比：引擎自己的相对误差在 5 层到 50 层之间一直稳定在 **1e-15 量级**（1.0e-17 ~ 1.6e-15），不随深度增长。真正随深度恶化的是**梯度本身的量级**（0.176 → 3.5e-9，衰减 5×10⁷ 倍）——那是梯度消失问题，不是精度问题。

## 我卡在哪

1. **把常数塞进了 `_children`**。`exp` 的输入只有一个 `self`，`math.e` 不是图里的节点；`x ** n` 里的指数 `n` 也一样。常数不参与求导，也不该进图。

2. **在前向分支里给 `out.grad` 赋值**。`out.grad` 是"上游传来的梯度"，`_backward` 里的系数才是"局部导数"。我把这两件事搞混了，还漏写了 `_backward` 本身——前向可以分支，反向必须挂上。

3. **`topo.append(child)` 缩进在 `for` 里面**。结果每个子节点被 append，但 `node` 自己从来没进过 `topo`，根节点的梯度永远不往下传。

4. **`if self._prev is None`**。`_prev` 是 `set()`，永远不会是 `None`。终止条件是"空集合"，不是"None"。

5. **`self.grad` 出现在等号右边**（`__pow__` 和 `__truediv__` 各犯一次）。累加器是接收方，不能当操作数——写成 `self.grad += f(...) * self.grad` 的话，初始是 0，乘完永远是 0，梯度一辈子是 0。

第 5 条最隐蔽：它不报错，只是让训练"不动"。

## 还有一个来回

第一版测试里我写的是：

```python
denom = max(1.0, abs(ana), abs(n))
rel = abs(ana - n) / denom
```

梯度很小时这个 `max(1.0, ...)` 会把**相对误差悄悄变成绝对误差**。深链那项显示 `8.55e-12`，看起来完美，实际相对误差是 `2.5e-3`。

后来改成 `allclose` 的标准形式 `|ana - num| <= atol + rtol * |num|`——**大梯度看相对、小梯度看绝对**，问题才暴露出来。

"我的测试在骗自己"这一课，比写引擎本身有用。

## 还没完全想明白的

PyTorch 的 autograd 引擎用的是 **ready queue**（依赖计数归零就调度），而不是先算一遍完整拓扑序再执行。我只能想到"这样能并行调度"，但还没找到它真正必须这么做的约束。
